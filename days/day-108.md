## Step-by-step explanation: behavior and why

Use this actual example: Training/development/held-out data stay separate; a CPU/offline path can inspect the same data and saved comparison results.

1. **Before:** name the input values, Python types, units, and state before the operation. Predict the observable result.
2. **Checks:** walk the applicable checks in their declared order: representation/shape → local value bounds → trusted identity/scope → business state. Skip checks that do not belong to this unit and explain their actual owner. Reject invalid input before an unauthorized or partial effect.
3. **Mechanism:** trace the calculation, branch, lookup, iteration, await, model/retrieval step, or transition using actual intermediate values. Explain the Python/library/system rule that causes each change; do not just narrate line names.
4. **After:** show the returned/displayed value and any permitted state change. Compare the observed outcome with the stated expectation. Name what remains unchanged.
5. **Failure variation:** change one relevant input or interrupt a dependency. Trace the different path, error, cleanup, cancellation, or recovery and explain why it behaves differently.

The walkthrough explains implementation behavior; it is not an undisclosed extra feature or test-authoring requirement. Use the learner's actual file/line and revision during review. If the learner asks for a fuller explanation, break the mechanism into smaller steps and examples.
