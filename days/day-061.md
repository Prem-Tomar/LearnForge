Week 09 · FastAPI and backend engineering · lesson · **180 minutes per developer**

## Explain before coding

Configuration changes deployment behavior. Secrets need protected injection; audit events record security-relevant actions without exposing credentials.

Explain the idea using a three-value example. Predict the result, run the example, and explain any difference. First choose the simplest correct behavior. Introduce a technical term only after explaining its meaning.

## Concrete behavior and boundaries

Missing signing configuration prevents startup; logs contain actor and outcome but no token or password.

The team writes down input shape, output shape, invalid-input result, and one failure outcome before implementation. These are internal working agreements, not a request to generate API documentation.

## System design connected to this task

Separate operational logs from security audit requirements, and limit who can access either.

Draw: **caller → today's boundary → state/dependency → result**. Name where invalid input is rejected and who owns state. Walk one failure using the concrete cases above. Compare one simpler alternative with the chosen design. In early weeks, four labeled boxes are enough; later add latency, capacity, consistency, permissions, and cost as relevant.
