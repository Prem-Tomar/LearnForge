# Small glossary

Use the daily example first. This page is a quick reminder, not a vocabulary exam.

| Term | Plain-English meaning |
|---|---|
| Interpreter | Program that runs Python instructions |
| Terminal | Text window where you ask programs to run |
| Value / variable | Data / a name referring to data |
| Type | Kind of value, such as integer or text |
| Mutable | Can be changed after creation |
| Function | Named operation with inputs and usually a result |
| Contract | Agreement about input, output, and failure behavior |
| Invariant | Rule that must remain true after valid operations |
| Exception | A reported failure that changes normal execution flow |
| Module / package | Importable Python file / organized collection of modules |
| Virtual environment | Separate package environment for a project |
| Class / object | Definition of a kind of thing / one instance of it |
| Protocol | Small set of behaviors a collaborator must provide |
| Iterator | Object that produces values one at a time and keeps its position |
| Generator | Function or expression that creates an iterator lazily |
| Decorator | Wrapper that adds behavior to a function or class |
| Context manager | Entry/exit behavior that helps manage a resource |
| Async | Cooperative execution that can let other work run while waiting |
| GIL | Interpreter lock affecting Python execution in common CPython builds |
| API | Interface through which one program uses another component |
| Endpoint / route | Application operation selected by an HTTP method and path |
| ASGI | Interface between an async Python web server and application |
| Validation | Checking whether input meets the stated rules |
| Authentication | Checking who the caller is |
| Authorization | Checking what the caller may do |
| Tenant | Customer/group whose data must stay isolated |
| Adapter | Translation between an internal agreement and an external system |
| ORM | Tool mapping database rows to program objects |
| Transaction | Changes committed together or rolled back together within a database scope |
| Index | Structure that speeds selected lookups at a storage/write cost |
| Migration | Versioned change to stored data structure |
| Idempotency | Repeating a request does not repeat its intended effect |
| Queue / worker | Pending-work buffer / process that performs that work |
| Backpressure | Slowing or rejecting input when processing cannot keep up |
| Outbox | Durable event intent stored with the business write in one transaction |
| Latency / throughput | Time for an operation / amount completed per unit time |
| p95 | Value at or below which 95 percent of observations fall |
| SLO | Measurable service-quality goal |
| Token | Model-specific piece of text or other input/output representation |
| Embedding | Numeric vector representing learned relationships in content |
| Chunk | Bounded searchable piece of a source |
| Provenance | Record of where data came from and which version it represents |
| RAG | Retrieving evidence before asking a model to generate an answer |
| Reranking | Rescoring a limited candidate set to improve its order |
| Grounding | Connecting an answer to supplied evidence |
| Abstention | Saying there is not enough support to answer |
| Hallucination | Generated claim unsupported by reliable evidence |
| Evaluation | Comparing observed behavior against defined examples and a rubric |
| Fine-tuning | Changing model parameters using training data |
| Quantization | Representing model numbers with lower precision |
| KV cache | Stored attention information reused during model generation |
| Agent | Component that uses a model to choose some next actions |
| Tool call | Proposed invocation of an exposed application operation |
| State machine | Named states and allowed transitions between them |
| Checkpoint | Durable record used to resume work |
| Compensation | New action intended to partly reverse an earlier effect |
| MCP | Protocol for connecting AI applications to external capabilities |
| Prompt injection | Untrusted content attempting to act as instructions |
| Cache | Saved result reused under a stated identity and freshness policy |
| Replication / partitioning | Copying data / distributing different subsets of data |
| RPO / RTO | Tolerable recovery data loss / tolerable recovery time |
| Big O | Description of how work or memory grows with input size |
| Fixture / fake | Reusable setup / simple replacement dependency used for small checks |
| Regression check | Example that catches a previously found failure returning |

The coach should add a brief definition when a daily guide introduces an unfamiliar term not listed here.
