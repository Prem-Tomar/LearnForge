# Python, FastAPI, GenAI, and AI agents — team coaching

**Six months · 26 weeks · 182 learning days · 598 scheduled hours per developer, including breaks.**

Learn through one growing product: **LearnForge**, a learning and knowledge platform. Start with a small working command-line program. Gradually add persistent study sessions, workspaces, authentication, document ingestion, cited answers, approved agent actions, durable jobs, operational controls, and recovery.

The default team has **two developers**. They implement separate parts, review each other, and rotate roles. Each person learns and proves every core concept individually. A third-person mode is included.

## Time and learning pattern

- **Five days × 3 hours**, then **two days × 4 hours**: 23 hours per week.
- Five focused implementation days, one integration day, and one individual mastery-and-repair day.
- Every day: a concrete task, examples, a system-design connection, **Question of the Day**, interview drill, pitfalls, quiz, individual proof exercise, peer review, and a working demonstration.
- Review and catch-up are inside the time budget. Unmet mastery gates stay open; the calendar does not turn incomplete understanding into a pass.

Use the two longer sessions on the days that suit the team. The schedule has no imposed calendar start date.

## Working agreements

**Simple English:** explain a term before expecting the learner to use it. Give a small example, predict its output, run it, and explain the result.

**No missed concepts:** both people complete the same concept goals and different isolated proof exercises. Roles rotate weekly; review crosses role boundaries. Individual scores cannot be replaced by a team score.

**No overlapping production work:** daily ownership names separate core, adapter, and product paths. Shared changes have one owner and happen before parallel implementation. See [TEAM.md](TEAM.md).

**Light testing:** learn useful patterns through feature work and a few short examples. There is no testing-only task or dedicated tester role. No coverage quota or large test-writing project is required.

**API documentation is opt-in:** do not add API documentation, Swagger, ReDoc, or a public OpenAPI endpoint unless the user asks. Future FastAPI setup disables those endpoints. Internal input/output agreements remain necessary for parallel work.

**Assignments:** issues currently use Developer 1 and Developer 2 roles and have no GitHub assignees. Invitations were left aside at the user's request; no collaborator invitations are claimed. No email addresses are published.
