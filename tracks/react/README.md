## Setup and exact placement

At activation, agree one browser build tool/router and record compatible React, TypeScript, runtime, and package versions in the client lockfile. Explain package installation, scripts, compiler, bundler, source maps, browser devtools, and browser-vs-server execution before relying on them. Avoid framework-specific server features until the learner can explain basic rendering and the FastAPI boundary. No app scaffold is committed by this plan.

Default root is `clients/web/`. Within it, `src/app/App.tsx` composes features; `src/api/` owns HTTP/auth details; `src/features/<feature>/` owns UI and feature state. Keep CSS beside the feature initially. The table uses a default owner per feature. If several selected learners share the web track, split exact feature roots before assignment and nominate one shared-file integrator. Everyone still proves all common React concepts in their own isolated exercise; reviewing another component alone is insufficient.

## Interview practice and mastery

Use the row's RQ question plus one previously taught JS question and one changed scenario. React-specific expectations are in [the coach key](../../coach/client-interview-key.md), separate from learner prompts. For example, after R05 ask the learner to predict subscription counts before/after a cleanup, then show the actual trace. After R08 ask what happens when the server commits but the browser loses the response. Answers must name actual state/IDs and explain why.

Each learner must independently implement and explain props/state/events, immutable updates and stable identity, effects/cleanup/dependencies, validated async data with stale-write prevention, forms/auth boundaries, accessible interaction, and debugging/deployment. A correct UI copied from a teammate is not personal evidence. R14 is an implementation/integration session with interviews attached, not a day assigned only to interviews or testing.

Deeper SSR/hydration, advanced browser caching/service workers, design systems, advanced accessibility and large-scale frontend architecture are follow-on topics if the chosen role needs them. Do not claim advanced mastery from these first fourteen increments. Fix gaps through fresh feature variations and measured evidence.

Official references: [Quick Start](https://react.dev/learn), [state snapshots](https://react.dev/learn/state-as-a-snapshot), [identity and resetting state](https://react.dev/learn/preserving-and-resetting-state), and [effect synchronization](https://react.dev/learn/synchronizing-with-effects). A render uses a snapshot of state; effects synchronize external systems and require appropriate cleanup. Re-read the relevant section against the versions selected at activation.
