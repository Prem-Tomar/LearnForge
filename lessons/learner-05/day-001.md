# Day 001: Your first small LearnForge function

You do not need previous Python knowledge. Today you will change one small function that supplies a value to LearnForge's welcome screen. A function is a named piece of code that runs when called. We explain it before you edit it.

## First: a variable and a running file

A variable is a name connected to a value. Save this example before running it:

```python
project_name = "LearnForge"
study_minutes = 30
print(project_name)
print(study_minutes)
```

Run `python examples/day-001/variables.py` from the repository folder. It prints:

```text
LearnForge
30
```

Line 1 connects `project_name` to text. Quotes mark text. Line 2 connects `study_minutes` to the number 30; the number has no quotes. `=` assigns a value; it does not ask whether two values are equal. Lines 3 and 4 ask Python to display the values. Assignment itself does not display anything. Change 30 to 45 in your own small copy, predict the result, save, then run.

## Next: a tiny function, indentation, return and call

```python
def welcome():
    message = "Learning LearnForge"
    return message

print(welcome())
```

Run `python examples/day-001/first_function.py`. It prints `Learning LearnForge`.

| Line | Purpose | Behavior and project contribution |
|---|---|---|
| `def welcome():` | Give the function a name | Defines it; its body runs when called later. Empty parentheses mean no arguments today. The colon starts its body. |
| Four spaces, then `message = ...` | Create the welcome value | Runs during the call and connects a local name to the screen's text. |
| Four spaces, then `return message` | Give a value back to the caller | Ends this call and supplies the text; it does not print. |
| Blank line | Make code easier to read | It does not display anything or change the value. |
| `print(welcome())` | Call, then display the result | Python calls `welcome()`, receives its text and gives it to `print`, making it visible. |

Use four spaces for the body; do not mix tabs and spaces. The last print line is outside the function. In a separate copy, remove the indentation after `def`, predict, run and read the error with the coach. Restore the indentation and run again. You do not need exception handling today.
